 RepuKeel SEO Implementation Spec for Antigravity Prepared 26 Oct 2026 | Site: https://repukeel.com/ | Stack: Next.js (confirmed from /_next/image URLs; App Router vs Pages Router not confirmed) This spec turns the SEO audit into tasks an AI coding agent can run in the RepuKeel repository. Every task has an ID, exact steps, acceptance criteria and a verification command. Work the agent cannot do (Search Console actions, business facts) is in Section 5. No task guarantees any ranking. 1. Agent operating rules Create branch seo/fixes-2026-10 . Make one commit per task with message SEO-XX: &lt;title&gt; . Detect the router first: ls app pages src/app src/pages 2&gt;/dev/null . App Router: use export const metadata , generateMetadata and export const viewport . Pages Router: use next/head . Never invent facts: statistics, testimonials, ratings, addresses, client names, prices, legal claims. If a task needs one, stop and list it in SEO-REPORT.md under Needs human input . Do not add keywords, titles or new content topics. Do not delete pages or change URL paths unless a task says so. Tasks marked Approval gate : write the proposal file, stop, and wait for human approval before editing code. Before each commit run npm run lint and npm run build (use the repo&apos;s own script names if different). Do not commit if the build fails. Verify on the local production build ( npm run start , http://localhost:3000). Re-verify on https://repukeel.com/ after deployment. After each task append to SEO-REPORT.md : task ID, files changed, acceptance result (pass/fail per criterion), commands run, open questions. If a finding does not reproduce in the code, mark it Not reproduced in the report and move on. Do not force a change. 2. SEO-03 Resolve 4 canonical conflicts Status: CONFIRMED (count); cause INVESTIGATE | Priority: Critical | Effort: S-M | Depends on: H-01, SEO-02 Finding: Search Console reports &quot;Duplicate, Google chose different canonical than user&quot; on 4 pages. Validation: Failed . The URLs are not in the export. Homepage canonical is https://repukeel.com (no trailing slash). Steps: Read the 4 URLs supplied by the human (H-01), saved as seo/canonical-urls.txt . For each, fetch the declared canonical: curl -s URL | grep -io &apos;&lt;link[^&gt;]*rel=&quot;canonical&quot;[^&gt;]*&gt;&apos; . Compare with Google&apos;s chosen canonical supplied in H-01. Classify cause: host variant, trailing slash, wrong canonical value, or near-duplicate page. Create one shared helper (for example lib/seo.ts exporting SITE_URL and canonicalFor(path) ). Use it in every page&apos;s canonical so the host and slash style are identical everywhere. Match trailingSlash in next.config.js to that style. For host or slash variants, add 301s in next.config.js redirects() to the canonical form. For near-duplicate pages, do not delete or merge. List them in SEO-REPORT.md under Needs human input . Acceptance: Every page&apos;s canonical equals its own final URL in the chosen host and slash style. Non-canonical variants 301 to the canonical in one hop. Near-duplicate pages are listed for human decision. Verify: for u in $(cat seo/canonical-urls.txt); do echo $u; curl -s &quot;$u&quot; | grep -io &apos;&lt;link[^&gt;]*rel=&quot;canonical&quot;[^&gt;]*&gt;&apos;; curl -sI &quot;$u&quot; | head -1; done . Human follow-up: After deploy, click Validate Fix in Search Console (H-02). Benefit: Google indexes the intended URL; removes the duplicate-signal conflict. SEO-04 Fix 3 redirect errors Status: CONFIRMED (count); cause INVESTIGATE | Priority: Critical | Effort: S | Depends on: H-01 Finding: Search Console reports &quot;Redirect error&quot; on 3 pages. Validation: Not Started. Usual causes: loop, chain too long, invalid target. Steps: Read the 3 URLs from H-01 ( seo/redirect-urls.txt ). Trace each: curl -sIL --max-redirs 10 URL | grep -iE &apos;^(HTTP|location)&apos; . Record the hop list. Find the rules: grep -rn &quot;redirects\|redirect(\|permanentRedirect\|NextResponse.redirect&quot; next.config.* middleware.* src app pages 2&gt;/dev/null . Fix loops, remove intermediate hops, and point each old URL to its final 200 page with one 301. Remove these URLs from the sitemap and from internal links. Acceptance: Every URL ends in a 200 after at most one redirect. No URL in a loop. Verify: for u in $(cat seo/redirect-urls.txt); do curl -sIL --max-redirs 10 -o /dev/null -w &quot;%{num_redirects} hops, final %{http_code}, %{url_effective}\n&quot; &quot;$u&quot;; done . Expect 0 or 1 hops and 200 . Human follow-up: Click Validate Fix (H-02). Benefit: Pages become crawlable and indexable; less crawl waste.
